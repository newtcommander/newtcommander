# Contract: `build.cmd` plugin-policy behavior

Extends the existing root build script contract (`build.cmd [rebuild]
[release] [full] [help]`). All existing flags, output paths, and the
exit-code convention (0 = success, non-zero = failure) are unchanged.

## New pipeline stages (every run, every flavor)

Order of operations:

1. **Prerequisites** (existing: OPENSAL_BUILD_DIR, MSBuild discovery).
2. **Plugin policy stage** (new) — invoke
   `src/vcxproj/gen_plugins_filter.ps1`:
   a. Parse + validate `plugins.cfg` (rules V1–V5, see
      `plugins-cfg.md`). Any violation → print
      `ERROR: plugins.cfg ...` naming the offending entry/line →
      `build.cmd` exits non-zero **before MSBuild runs**.
   b. Generate `src/vcxproj/salamand.gen.slnf` containing every
      `salamand.sln` project except those under `..\plugins\<name>\`
      for each disabled plugin.
   c. **Reconcile output** (if `<out>\plugins\` exists):
      - delete `<out>\plugins\<name>\` for every disabled plugin;
      - delete any `<out>\plugins\<dir>\` matching no current plugin
        directory (leftovers of removed plugins), preserving
        non-plugin artifacts (`plugins.ver`, `Intermediate` dirs);
      - if `<out>\plugins\plugins.ver` exists, drop entry lines whose
        `.spl` path belongs to a non-enabled plugin (header line kept).
3. **MSBuild** (existing invocation, retargeted):
   `MSBuild salamand.gen.slnf /t:<build|rebuild> /p:Configuration=...`
4. **Full-build extras** (existing `:populate_runtime`, amended):
   - runtime data copies that belong to a plugin run only when that
     plugin is enabled (`automation` sample scripts, `zip` zip2sfx
     samples); the `ieviewer` CSS step is deleted with the plugin;
   - `plugins.ver` regenerated by scanning `.spl` files (unchanged
     logic — correct by construction after reconciliation).

## Observable guarantees

| Guarantee | Source requirement |
|---|---|
| Disabled/removed plugin is never compiled and its files are absent from `<out>\plugins\` after any run | FR-005, FR-006 |
| `plugins.ver` (when present) lists exactly the enabled plugins | FR-006 |
| Toggling one config line is the only change needed to add/remove a plugin from the product | FR-007, SC-003 |
| All five config error classes abort with exit ≠ 0 and an entry-naming message, before compilation | FR-009, FR-010, SC-004 |
| Summary block reports the enabled-plugin count actually shipped | SC-001 (observability) |

## Helper script interface (`gen_plugins_filter.ps1`)

```text
powershell -NoProfile -ExecutionPolicy Bypass -File src\vcxproj\gen_plugins_filter.ps1
    -Config      <repo>\plugins.cfg
    -Solution    <repo>\src\vcxproj\salamand.sln
    -OutSlnf     <repo>\src\vcxproj\salamand.gen.slnf
    -PluginsRoot <repo>\src\plugins
    [-OutputPluginsDir <out>\plugins]      # when present: perform reconciliation
```

- Exit 0 on success; exit 1 with `ERROR: ...` lines on any V1–V5
  violation or I/O failure.
- Prints one `Plugins: N enabled, M disabled` summary line consumed by
  build.cmd for the final report.
- Deterministic: same inputs ⇒ byte-identical `.slnf` (stable project
  ordering as found in the `.sln`).
